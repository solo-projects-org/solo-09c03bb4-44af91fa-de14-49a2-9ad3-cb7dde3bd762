# 罕见病病例合计发布核查

罕见病研究数据员在公布若干人群组的病例合计前，用本系统核查该合计与**总人数、历次已公布合计**联立后，是否会唯一确定某个保密组（实际 1～4 人）的人数。

- **FastAPI** 网页 + **SQLite** 持久化（重启后沿用原底表与发布历史）
- **SciPy `milp`** 求整数解：把各组人数当作未知非负整数（0～1000），仅以总人数、历次已公布合计和本次合计为约束；若某保密组在全部可行底表中的人数都相同，则拒绝并指出组名
- 首次上传 CSV 后底表固定（2～16 个唯一组名，人数 0～1000 的整数）
- 并发申请由全局锁串行化，按实际发布次序核查累计结果，不会“各自通过后共同泄密”
- 拒绝、求解无定论或保存失败时，本次合计不发布，历史不变

## 启动

```bash
docker compose up --build
# 打开 http://localhost:8000
```

本地开发（Python 3.11+）：

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

数据存于 SQLite（容器内 `/data/app.db`，挂载在命名卷 `app-data`）。重置演示数据：

```bash
docker compose down -v
```

## 网页演示“组合泄露”（sample.csv）

`sample.csv` 共 5 组：Alpha=3（保密组）、Beta=5、Gamma=10、Delta=0、Epsilon=7，总人数 **25** 公开。

1. 打开首页，上传 `sample.csv`，底表固定。
2. 勾选 **Alpha、Beta** → 公布合计 **8** ✅（此时 Alpha 可能为 0～8，未泄露）
3. 勾选 **Alpha、Gamma** → 公布合计 **13** ✅（仍未唯一确定 Alpha）
4. 勾选 **Beta、Gamma** → **拒绝** ❌：25、8、13、15 四个等式联立可唯一推出 Alpha=3（同时确定 Beta=5、Gamma=10，但二者非保密组），页面指出泄密组名「Alpha」，历史不变。

即：任意两次合计各自安全，组合起来即泄露——正是本系统要拦截的情形。

## 核查逻辑

对每次申请（选组 S、合计 s），构造线性等式约束（未知数 xᵢ = 各组人数，0≤xᵢ≤1000 整数）：

- Σxᵢ = 总人数（公开）
- 每条历史记录：Σ_{i∈Sⱼ} xᵢ = sⱼ
- 本次申请：Σ_{i∈S} xᵢ = s

对每个保密组 p，用 SciPy MILP 分别求 xₚ 的最小、最大可行值：若相等，则 p 的人数被唯一确定 → 拒绝并列出组名；求解器未返回最优解视为“无定论”，同样不发布。核查与写入历史在同一把全局锁内完成，保证并发请求按实际发布次序看到累计历史。
