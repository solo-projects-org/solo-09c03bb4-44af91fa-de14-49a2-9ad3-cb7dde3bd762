# 罕见病人群组合计发布 · 组合泄露核查服务

罕见病研究数据员需要公布若干人群组的病例合计，但每次发布前必须核对：
把**各组人数当作未知非负整数**，仅以公开的总人数、历次已公布合计与本次合计
建立约束后，任何真实人数为 1～4 的保密组，其人数是否会在**全部可行整数底表**
中被唯一确定。若是，则拒绝本次发布并指出组名；否则保存选组与合计，列入发布历史。

## 技术栈

| 关注点 | 选型 |
| --- | --- |
| Web 框架 | FastAPI + Uvicorn |
| 持久化 | SQLite（底表、发布历史；重启沿用） |
| 整数解核查 | SciPy `optimize.milp`（HiGHS 混合整数线性规划） |
| 部署 | Docker Compose（命名卷持久化数据库） |

## 目录结构

```
app/
  main.py        FastAPI 路由、进程级发布锁、错误语义
  checker.py     MILP 核查：保密组变量逐次最小化/最大化判定是否唯一
  database.py    SQLite 建表与原子写入
  csv_utils.py   底表 CSV 解析与校验
  static/index.html  单页操作界面（上传、勾选、发布、历史）
samples/groups_sample.csv  可直接演示组合泄露的样例数据
tests/           pytest 测试（核查逻辑、API、并发、重启持久化）
Dockerfile / docker-compose.yml
```

## 快速启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

SQLite 数据库保存在命名卷 `le-check-data`（容器内 `/data/app.db`），
容器重启或重新创建后底表与发布历史自动沿用。停止并清除数据：

```bash
docker compose down          # 仅停止，保留数据
docker compose down -v       # 连同数据库卷一起删除
```

## 本地直接运行（无 Docker 时）

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
# 数据库默认在 ./data/app.db，可用环境变量 APP_DB_PATH 覆盖
```

## 核查模型（app/checker.py）

设 n 个组的未知人数为非负整数变量 `x_0, …, x_{n-1}`，攻击者可用的全部等式约束为：

1. 公开总人数：`sum(x_i) = T`
2. 每条已发布记录 j：选中组 `sum(x_i) = 合计_j`
3. 本次申请：选中组 `sum(x_i) = 本次合计`

对每个**保密组**（底表中真实人数 ∈ [1,4] 的组），分别求解该变量在上述约束下的
最小值与最大值（两次 MILP）。两者相等意味着该组人数在所有可行整数底表中取值唯一，
即发生泄露，返回组名并拒绝发布。求解器未返回最优解（超时、数值问题等）按
**无定论**处理，同样不发布。模型只使用公开信息，不把“0～1000 取值范围”等
底表私有上限当作攻击者已知条件。

## 并发正确性

发布接口在进程级 `threading.RLock` 内串行执行“读取累计历史 → MILP 核查 →
写入新记录”。每个申请都基于它**实际取得锁时**的历史重新核查，因此并发申请
严格按实际发布次序逐条接受/拒绝，不会出现各自单独通过、合起来泄密的情况。
拒绝、求解无定论或保存失败时本次合计不发布、历史不变（SQLite 事务回滚）。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 操作界面 |
| GET | `/api/state` | 底表（含保密标记）、总人数、发布历史 |
| POST | `/api/upload` | 首次上传 CSV 并固定底表；重复上传返回 409 |
| POST | `/api/publish` | 提交 `{"groups": [...]}`；泄露返回 422 并给出 `leaked_groups`，无定论 503，保存失败 500 |

## 网页演示：组合泄露（样例 CSV）

`samples/groups_sample.csv`：

| 组 | 人数 | 状态 |
| --- | --- | --- |
| A | 2 | 保密（1～4 人） |
| B | 10 | 非保密 |
| C | 20 | 非保密 |
| D | 68 | 非保密 |

总人数 100 视为公开。按顺序在网页勾选（页面上有同名快捷按钮）：

1. **B + C**，合计 30 → 通过。此时 A 可取 0～70 的任意整数，无法确定。
2. **A + C**，合计 22 → 通过。联立 B+C=30 后，A 仍可在 0～22 间变化。
3. **A + B**，合计 12 → **被拒绝，点名 A**：
   三式联立 `A = (22 + 12 − 30) / 2 = 2`，A 在所有可行整数底表中唯一。
   本次合计不写入，发布历史仍只有前两条。

另外可直接验证两种更直观的泄露：

* 只勾选 **A**（合计 2）：A 被等式直接确定，拒绝；
* 勾选 **B + C + D**（合计 98）：与公开总人数 100 互补，`A = 100 − 98 = 2`，拒绝。
